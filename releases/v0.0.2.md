# project-workflow v0.0.2

引入**两套独立版本体系**：Skill 本体版本与模板版本分开演进。上一个版本（v0.0.1）只能回答「这份 Skill 是不是最新」，无法回答「我在某个项目里植入的模板是不是最新、我改过没有、升级会不会覆盖我的改动」。本版本补上这一层。

## 新增能力

**模板版本体系**

- `templates/manifest.json` 记录当前 `template_version` 与五个模板文件的 sha256。
- `templates/manifest-history/` 保存历史基准：`1.0.json`、`1.1.json`，以及 `pre-marker.json`（收录 v0.0.1 之前出现过的全部历史模板内容，哈希数组，任一命中即视为未改动）。
- 模板文件首行植入 marker（`<!-- project-workflow: template-version=<版本> installed=<日期> -->`，`.gitattributes` 用 `#` 注释），安装后即可被识别。
- 项目内 marker 是**版本真相**；registry 只是索引，不作为判定依据。

**升级判定**

- 有 marker：比较版本，落后则提示。
- 无 marker 但哈希命中历史基准（`pre-marker`）：按旧版处理，正常升级并补写 marker。
- `legacy`：命中三条信号中至少两条——哈希不命中任何基准、体量与模板悬殊、Git 首次提交早于 `v0.0.1`——判为**自有文档而非模板实例**，不写 marker、不升级、不纳入模板管理，只做存在性说明。
- 仅一条信号成立：不下结论，报告「疑似非模板植入」交用户确认。

**Skill 本体升级**

- `snapshot.json` 记录安装时各文件的 sha256（本机状态，不入库）。升级时逐文件比较：未改动则替换，已改动则保留并报告差异，不再依赖人工逐份比对。

**新增参考文档**

- `VERSIONING.md`：维护者向的设计说明，含问题背景、构件总览、数据格式、升级行为表、检测流程、边界与限制，以及本次核查的实证记录。
- `references/upgrade.md`：执行向的操作规范，含安装、本体升级、模板升级、落后检测的完整步骤。
- `SKILL.md` 第 3、4 节按需引用上述文档，不默认加载。

## 模板 1.0 → 1.1

`template_version` 提升到 1.1，内容来自对若干真实项目治理文档的提炼（这些项目本身不纳入模板管理，见上文 `legacy`）：

- `WORKFLOW.md`：新增「决定与记录是两件事」「状态定义」（8 状态及各自由谁决定，含「待验收 ≠ 已验收」）「状态一致性」「文件职责边界」。
- `BACKLOG.md`：状态集合扩到 9 个并与 `WORKFLOW.md` 对齐；任务标识只增不减、永不复用；否决与废弃必须写原因。
- `AGENTS.md`：「已知陷阱」新增三条通用规则——「查不到」不等于「不存在」、一次测量不是结论、同一功能不要并行维护多种写法。
- `README.md`：新增「项目结构」表（路径 × 职责）。
- `.gitattributes`：补 `*.ps1 text eol=crlf` 与归档/可执行文件的 binary 声明。

## 兼容性

- 已安装 v0.0.1 且使用 junction 或复制方式安装的，按 `INSTALL.md` 的更新步骤处理；安装脚本仍不覆盖已存在的目标。
- 模板升级**永不静默覆盖**项目文件。无法确认归属时只报告，交由用户裁决。
- 新增文件均不引入运行时依赖，仍是纯 Markdown。
- `.gitignore` 增加 `.memsearch/`（本机会话记忆，含本机绝对路径）。

## 验证与限制

- 四个 JSON 清单合法；`manifest.json` 的五个 sha256 与 `templates/` 实际文件逐条匹配；五个 marker 均可被统一正则提取。
- `legacy` 判定以真实项目实测，并以临时目录做五组反向测试（原样植入、植入后修改、删去 marker、自制文档、空目录），未出现误判为 `legacy` 的情况。
- 全部 Markdown 文件本地链接检查通过；`git diff --check` 通过。
- **未实现**：基于哈希的逐段三方自动合并（冲突仍为「报告 + 用户裁决」）；`snapshot.json` 与 `registry.jsonl` 的一键生成/校验脚本（规范中仅给命令片段）。
- 未逐一运行各 Agent 产品的安装与行为验收；`tests/scenarios.md` 是待执行的行为评估清单，不代表已通过。
- 详细检查记录见 `tests/validation.md`。

## 安装

下载本页 Source code ZIP 或 tar.gz，按仓库 `INSTALL.md` 将完整 Skill 内容复制到目标 Agent 的技能目录。纯 Markdown，无运行时依赖。
